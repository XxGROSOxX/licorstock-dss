# Retrospectiva Sprint 1 - Starfish

## Proyecto

LicorStock DSS

## Objetivo de la retrospectiva

Analizar el desempeño del Squad durante el Sprint 1, identificando prácticas que funcionaron, bloqueos encontrados y mejoras concretas para el Sprint 2. La retrospectiva se realizó bajo un enfoque de seguridad psicológica, buscando soluciones y no culpables.

## Directiva primaria

Independientemente de lo que descubramos, entendemos y creemos sinceramente que todos hicieron el mejor trabajo posible con los conocimientos, recursos y tiempo disponibles.

## Tablero Starfish

| Categoría   | Aportes del Squad                                                                                                                                                                                                                                                                       |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keep Doing  | Mantener el uso de GitHub Projects para organizar las historias de usuario. Mantener la separación del backend por capas: routes, controllers y services. Mantener las pruebas manuales antes de mover una historia a Done. Mantener la integración entre frontend, backend y Supabase. |
| Less Of     | Reducir la improvisación al configurar el proyecto en máquinas distintas. Reducir cambios grandes sin hacer commits intermedios. Reducir el tiempo perdido por errores de rutas, nombres de archivos o versiones de Node/Vite.                                                          |
| More Of     | Documentar mejor los pasos técnicos y evidencias. Hacer más pruebas de endpoints antes de conectar frontend. Revisar más seguido los criterios de aceptación. Hacer más capturas durante el desarrollo para no buscarlas al final.                                                      |
| Stop Doing  | Dejar de programar sin verificar primero el entorno. Dejar de cerrar tareas sin evidencia. Dejar de trabajar con archivos vacíos o sin exportaciones en React. Dejar de dejar la documentación para el último momento.                                                                  |
| Start Doing | Empezar cada Sprint con un checklist técnico de entorno. Crear una tarea fija de revisión de calidad antes de la demo. Hacer revisión cruzada de código entre compañeros. Registrar en GitHub cada mejora del proceso como una tarea del Sprint.                                        |

## Conclusión

La retrospectiva permitió identificar que el equipo logró completar funcionalidades importantes, pero también evidenció problemas de configuración, documentación tardía y falta de revisión previa. Para el Sprint 2 se priorizará mejorar la estabilidad del entorno y fortalecer la validación antes de cerrar historias.
